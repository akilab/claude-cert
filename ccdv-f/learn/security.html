セキュリティと安全 配点 8.1%

プロンプトインジェクションへの対策、ガードレール、フックによる制御、シークレットの管理、個人情報の扱いを学びます。キーワードは「モデルの判断に頼らず、仕組みで守る」です。

この章の前提：はじめに（前提知識）の API キー・認証と認可・ツール利用の流れ

プロンプトインジェクション

外部の文書・Web ページ・メールなどに埋め込まれた命令に、モデルが従ってしまう攻撃です。利用者が直接入力する場合（直接）と、Claude が読む資料に仕込まれる場合（間接）があります。仕込まれる場所や被害までの流れは 文書やメールに仕込まれた命令 で図を使って詳しく説明しています。

対策効果
信頼できない入力を指示と分ける（タグで囲む、データであると明記）騙されにくくする（完全ではない）
最小権限：役割に必要なツール・権限だけを渡す（→ 最小権限の図解）騙されても被害が出ない
重要な操作（送信・送金・削除）は承認やフックで止める騙されても実行されない
出力の検査、監視異常を見つける
「system に『従わないで』と書く」「大きなモデルにする」「temperature を変える」は、単独では強制力のない対策。分離＋最小権限＋承認・フックが正解の軸。

ガードレールと安全な展開

どの対策も単独では完全ではないので、性質の違う対策を重ねます（多層防御）。

  1. 入力の検査（不適切な依頼、機密情報の要求）
  2. system での方針（できること・できないこと）
  3. ツールの最小権限、重要な操作の承認
  4. 出力の検査（個人情報、方針違反）
  5. 監視とアラート

セキュア・バイ・デザイン：プライバシー、ID とアクセスの管理、最小権限を、後付けではなく最初の設計に組み込みます。

フックで破壊的な操作を防ぐ

  • フックはモデルの判断に関係なく必ず実行されるので、「確実に防ぐ」用途に向いている。
  • Claude Code では、settings.json の権限ルール（許可・拒否）と組み合わせる。
  • CLAUDE.md の「やめて」は補助。強制はフックと権限で。

ID・シークレット・キーの管理

✕

  • ブラウザの JavaScript にキー
  • ソースコード・Git にキー
  • 開発と本番で同じキー
  • チャットでキーを共有

◯

  • サーバー側でシークレット管理から読む
  • 環境ごとにキーを分ける
  • 定期的に入れ替える。漏れたらすぐ無効化
  • 使用状況を監視する

利用者の本人確認・認可（誰が何をできるか）も、モデルではなくアプリの仕組みで行います。

個人情報（PII）の扱い

  • 必要な範囲だけをモデルに渡す（データの最小化）。
  • ログには伏せ字にしてから書く。アクセス権と保存期間を制限する。
  • データの保存場所や保持の規定に合う提供元・設定を選ぶ。
  • 出力にも個人情報が含まれうるので、出力側でも検査する。

この分野のまとめ

  • インジェクション：分離＋最小権限＋承認・フック。お願いだけに頼らない。
  • ガードレールは多層に。セキュア・バイ・デザイン。
  • 確実に止める → フック＋権限ルール。
  • キーはサーバー側・環境別・定期交換・監視。PII は最小化と伏せ字。
