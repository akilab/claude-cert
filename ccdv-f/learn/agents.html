エージェントとワークフロー 配点 14.7%

いつエージェントを使い、いつワークフローにするか。エージェントをどう作り、どう安全に止めるか。代表的なパターンとフレームワークまでを扱います。

この章の前提：はじめに（前提知識）の ツール利用とエージェントの考え方・プログラムの読み方・サーバーはどこにある？

ワークフローか、エージェントか

観点ワークフローエージェント
手順事前に決まっている入力ごとに変わる・探索が必要
予測しやすさ・テスト高い低い（ばらつく）
費用・時間小さく一定大きく、ばらつく
例請求書の抽出 → 検算 → 登録障害の原因調査、コードベースの修正

原則は「最も単純な方法から」。1回の呼び出し（検索やツール付き）で足りるならそれで、決まった手順ならワークフロー、手順を決められないときにエージェントを選びます。

マネージャー／スーパーバイザーとサブエージェント

  • 親（マネージャー）は計画と統合を担い、子（サブエージェント）は独自のコンテキストで作業する。
  • 大量の途中経過が親に溜まらないので、コンテキストの肥大化を防げる。並列化もできる。
  • 子からの返却は、結論・根拠・出典などの決まった形式の要約にする。

Claude でエージェントを作る

Claude Agent SDK

Claude Code を支える仕組み（エージェントのループ、組み込みツール、コンテキスト管理、権限、フック、サブエージェント、MCP 連携など）を、部品として自分のアプリで使えるようにしたものです。一から作る手間を省き、独自の機能はカスタムツールやフックで足します。

独自のエージェントループ

while 繰り返し回数 < 上限:
    res = Messages API を呼ぶ（tools つき、履歴つき）
    if res.stop_reason != "tool_use": break        # 最終回答
    履歴に res.content（assistant）を追加
    結果 = 各 tool_use を実行（失敗は is_error: true）
    履歴に tool_result（user）を追加
else:
    上限に達した → 停止して状況を報告

細かい制御が必要なときは自分でループを書きます。その場合、停止条件（最大回数・トークンや時間の予算）、エラーを正直に返すこと、記録（トレース）を必ず入れます。

フックで「必ず」行う

フックは、ツールの実行前後などの決まったタイミングで、モデルの判断と関係なく必ず実行される処理です。

タイミング（例）使い方
ツールの実行前（PreToolUse）危険なコマンドをブロック、入力の検査
ツールの実行後（PostToolUse）編集後に必ずフォーマッターやテストを実行、記録
セッションの開始・終了など文脈の読み込み、通知、後片付け
「必ず」「確実に」「忘れてはならない」→ プロンプトの指示ではなくフック（決定的な仕組み）。

デプロイの方式

セルフホスト

  • 自社の環境で実行
  • 内部ネットワークやデータに直結
  • 実行環境・ログを自社で管理

Anthropic がホスト

  • 実行環境の運用を任せられる
  • 素早く始められる
  • 内部システムとの接続方法は要確認

代表的なパターン

パターンしくみ向いている場面
プロンプトチェーン決まった順に処理をつなぎ、途中で検証手順が明確な多段処理
ルーティング入力を分類して、適した処理やモデルに振り分け種類の違う入力が混ざる
並列化独立した部分を同時に処理、または同じ課題を複数回解いて多数決速さ・信頼性を上げたい
オーケストレーター／ワーカー計画役が動的に仕事を分け、ワーカーに任せて統合分け方が事前に決まらない大きな課題
評価者／改善者生成役と評価役で繰り返し改善明確な評価基準があり、改善の余地が大きい

メモリとコンテキストの管理

  • 長い作業は、進捗や決定事項をファイルなどの外部メモリに書き出し、次のセッションで読み込む。
  • コンテキストが膨らんだら、要約して圧縮する（コンパクション）、古いツール出力を削る。
  • 重い調査はサブエージェントに分ける。

フレームワーク

LangGraph、Strands、PydanticAI などのフレームワークは、状態の管理・分岐・再試行・可視化などの骨組みを提供します。

利点

  • 多段の処理を速く組める
  • 流れを図やグラフで共有しやすい

注意点

  • 抽象化の内側で送られるプロンプトが見えにくい
  • 品質は評価で確かめる必要がある
  • 料金は変わらない

この分野のまとめ

  • 単純な方法から。決まった手順はワークフロー、探索が必要ならエージェント。
  • サブエージェントでコンテキストを分離。返却は要約で。
  • ループには停止条件。「必ず」の処理はフック。
  • パターン：チェーン・ルーティング・並列化・オーケストレーター／ワーカー・評価者／改善者。
