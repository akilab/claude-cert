最小権限（least privilege） 全分野

最小権限とは、エージェントやツールに、その仕事に必要な権限だけを渡すという考え方です。セキュリティの問題では、選択肢の「正解の軸」になることがとても多い言葉です。この章では、なぜ必要なのか、具体的に何を絞るのかを、図と例で説明します。

試験との関係：「セキュリティと安全」の分野（AI アプリのセキュリティ、ガードレール、ID とキーの管理、Claude Code のフック）が中心です。ほかに、エージェントの設計（どのツールを渡すか）や Claude Code の設定（権限のルール）の問題にも出てきます。

最小権限とは：ひとことで

ホテルを思い浮かべてください。泊まる人に渡すのは、自分の部屋だけが開くカードキーです。全部の部屋が開くマスターキーは渡しません。マスターキーをなくしたり盗まれたりすると、全部の部屋が開いてしまうからです。

Claude を使ったアプリでも同じです。エージェントに渡すツールや、ツールが使える権限は「鍵」にあたります。仕事に使わない鍵は、最初から渡さない。これが最小権限です。

権限
何をしてよいかの範囲。「このデータを読んでよい」「このファイルを消してよい」「このメールを送ってよい」など。
ツール
Claude に使わせる道具（関数）。ツールを渡すことは、その操作をする権限を渡すことと同じです。

なぜ必要か：AI はだまされることがある

Claude は、読ませた文書やメールの中に紛れ込んだ命令に、引きずられてしまうことがあります（プロンプトインジェクション）。指示とデータを分けるなどの対策で減らせますが、完全には防げません。

そこで発想を変えます。「だまされないようにする」だけでなく、だまされても、持っている権限以上のことはできないようにしておくのです。

だまされることは防ぎきれない。だから、だまされても被害が小さく済むように権限を絞る

だまされたときだけではありません。モデルが指示を取り違えたときや、ツールの選び方を間違えたときも、渡していない操作はそもそも実行できません。また、ツールの数が少ないほど、Claude がツールを選び間違えることも減ります。

覚え方：被害の大きさは、渡した権限の広さで決まる。「念のため」で渡した権限は、だまされたときにそのまま攻撃者の道具になります。

何を絞るのか：5つの対象

「権限を絞る」といっても、対象は1つではありません。次の5つを順に確かめます。

対象最小権限にした例ありがちな失敗
① ツールFAQ に答えるエージェントには、FAQ の検索ツールだけを渡す「あとで使うかも」と、メール送信やファイル削除のツールも渡しておく
② 操作データベースを調べるツールは、読み取り専用の接続で動かす書き込みもできるアカウントで、参照だけの処理を動かす
③ データ社員の質問には、その社員が見てよい文書だけを検索して渡す全文書を検索して渡し、「権限のない情報は答えないで」とプロンプトで頼む
④ 鍵開発用と本番用でキーを分け、ツールのトークンは読み取りだけの範囲で発行する管理者の権限を持つキーを、すべての処理で共有する
⑤ 環境Claude Code では、必要なコマンドだけを許可し、危険な操作は deny ルールで止める確認をすべて省くモード（bypassPermissions）を、ふだんの開発の PC で使う

例で追う：社内ヘルプデスクのエージェント

社員からの質問（「有給はあと何日？」「出張の精算のルールは？」）に答えるエージェントを作るとします。どのツールを渡すかを、次の手順で決めます。

候補のツールを1つずつ判断すると、次のようになります。

候補のツール必要か判断
社内規程の検索必要読み取りだけで渡す
休暇の残り日数の参照必要質問した本人のデータだけを、本人の権限で読む
全社員の人事データの参照不要渡さない
休暇の申請の登録場合による渡すなら、登録の前に本人の確認（承認）を挟む
メールの送信不要渡さない。情報を外に持ち出す口になる
ファイルの削除不要渡さない

こうしておけば、メールの中の命令にだまされても、エージェントにできるのは「規程を読む」「本人の休暇を読む」ことだけです。

本人の権限で動かす：認可をモデルに任せない

③データの絞り方で、特に間違えやすいところです。社員Aの質問に答えるのに、全員のデータを読めるアカウントで検索してはいけません。

プロンプトに「権限のない情報は答えないで」と書いても、それはお願いであって強制ではありません。だまされたり取り違えたりすれば、渡したデータは出てしまいます。誰が何を見てよいか（認可）は、アプリの仕組みで決めるのが原則です。言葉の違いは 認証と認可 にあります。

「他人のデータが答えに出てしまう」→ 正解は「質問した本人の権限で検索し、見てよいデータだけを渡す」。「プロンプトで答えないよう指示する」は強制力がないので不正解になりやすい。

Claude Code での最小権限

Claude Code は、手元のファイルを読み書きし、コマンドを実行できるエージェントです。だから、ここでも最小権限が大事です。

権限のルールで絞る

.claude/settings.json（チームで共有する設定）の例：

{
  "permissions": {
    "allow": ["Bash(npm run test *)"],
    "deny":  ["Read(./.env)", "Bash(git push *)"]
  }
}
  • allow：確認なしで使ってよいもの。よく使う安全なコマンドだけを書く。
  • deny：使わせないもの。秘密の情報（.env）を読む、勝手に push する、などを止める。deny はいつも優先されます。

サブエージェントのツールを絞る

---
name: code-reviewer
description: 変更されたコードを読んでレビューする
tools: Read, Grep, Glob
---

レビューする係なので、読むツールだけを渡します。tools を書かないと、親のツールをすべて受け継ぎ、編集やコマンドの実行もできてしまいます。

自動実行（CI）で絞る

claude -p "この差分をレビューして" --allowedTools "Read"

人が確認できない自動実行では、--allowedTools で必要なツールだけを許可します。確認をすべて省く bypassPermissions は、外から隔離された使い捨ての環境でだけ使います。

設定の詳しい書き方は、用語集の 権限のルール・権限モード・サブエージェント にあります。

CLAUDE.md に「.env は読まないで」と書くのも、プロンプトと同じお願いです。確実に止めたいなら、deny ルールやフックを使います。

予防と検知：まず「外す」

危険を減らす対策には強さの順番があります。最小権限は、いちばん上の「外す」にあたります。

ログや確認の画面も大事ですが、それは「起きたことに気づく」「起きる前に人が見る」ための補いです。要らない権限が残っているなら、まず外す。そのうえで、業務に必要で外せない危険な操作（送金・削除・外部への送信）にだけ、承認やフックを重ねます。

「不要な権限が付いているが、ログで監視している」「確認の画面を出している」→ 足りない。最小権限の答えは「不要な権限を外す」。ログや確認は、外したうえでの追加の対策。

紛らわしい言葉との違い

言葉意味最小権限との関係
多層防御性質の違う対策を重ねる考え方最小権限は、その層の1つ
ヒューマン・イン・ザ・ループ重要な操作の前に人が確認する外せない危険な操作に、最小権限と組み合わせて使う
認証と認可「誰か」を確かめる／「何をしてよいか」を決める最小権限は、認可を「必要な分だけ」にする考え方
ガードレール入力・出力の検査など、安全のための仕組みの総称最小権限もガードレールの一部
監査ログ誰が何をしたかの記録検知の対策。最小権限（予防）の代わりにはならない

試験での見分け方

問題文のサイン正解になりやすい答え引っかけ
エージェントがだまされて、情報を外部に送った不要なツール（送信など）を外す。信頼できない入力を指示と分けるプロンプトに「従わないで」と書くだけ
「念のため」多くのツールを渡している役割に必要なツールだけにするツールの説明文を詳しくする
他人のデータが答えに出てしまう本人の権限で検索し、見てよいデータだけを渡す「答えないで」とプロンプトで指示する
不要な権限があるが、ログで監視しているまず不要な権限を外すログの項目を増やす、確認の画面を増やす
送金・削除が業務でどうしても必要外さずに、実行の前に人の承認やフックを入れる確認なしで自動で実行させる
CI で Claude Code を動かす--allowedTools で必要なツールだけを許可するbypassPermissions ですべての確認を省く

この章のまとめ

  • 最小権限＝その仕事に必要な権限だけを渡す。使わない鍵は最初から渡さない。
  • AI はだまされることがある。だから「だまされても、持っている権限以上のことはできない」ようにしておく。被害の大きさは、渡した権限の広さで決まる。
  • 絞る対象は5つ：ツール、操作（読む／書く）、データの範囲、鍵（キー・トークン）、動く環境。
  • 誰が何を見てよいか（認可）は、プロンプトのお願いではなくアプリの仕組みで決める。本人の権限で検索する。
  • Claude Code では、deny ルール、サブエージェントの tools、CI の --allowedTools で絞る。
  • 対策の強さは「外す ＞ 止める ＞ 見張る」。要らない権限があるなら、まず外す。
