ツールと MCP 配点 10.6%

ツールの実装、MCP サーバーの開発、そして組み込みツール・カスタムツール・Skills・MCP の使い分けを扱います。

この章の前提：はじめに（前提知識）の ツール利用の流れ・JSON Schema・標準入力・標準出力・認証と認可

ツールの実装

ツールの基本の流れは Messages API 解説のツール利用 と 疑似環境の演習5 で確認できます。

良いツール定義

✕ 曖昧

{"name": "search",
 "description": "検索する"}

◯ 具体的

{"name": "search_orders",
 "description": "注文履歴を検索する。利用者が注文の状況・配送・返品を尋ねたときに使う。order_id（例：A-00123、先頭のゼロも含む文字列）か email のどちらかが必要。注文の状態と日付を返す。"}
  • 何をするか・いつ使うか・入力の意味と形式・何が返るかを書く。
  • 入力の型を正しく定義する（ID は文字列。数値にすると先頭のゼロが消える）。
  • 似たツールを増やしすぎない。目的ごとにまとまったツールにする。
  • 出力は必要な情報に絞る（巨大な JSON をそのまま返すとコンテキストを圧迫する）。

エラーの返し方

失敗も tool_result で返します。is_error: true を付け、何が起きたか・再試行できるかを簡潔に。架空の結果を作ったり、結果を返さなかったりしてはいけません。

使い方のパターン

パターン内容
クライアントツールアプリが実行して結果を返す
サーバーツールAnthropic 側で実行（web_search、code_execution など）
承認のパターン影響の大きいツール（送金・削除・送信）は、実行前に人の承認を挟む
ハーネスでの振り分けエージェントの実行基盤（ハーネス）が、要求されたツールを適切な実装に振り分け、権限を確認する

MCP サーバーの開発

MCP（Model Context Protocol）は、ツールやデータを Claude のアプリにつなぐための共通の規格です。一度サーバーを作れば、MCP に対応したアプリ（Claude Code、Claude Desktop、Agent SDK で作ったアプリなど）から同じ方法で使えます。

MCP が提供するもの内容
toolsClaude が呼び出せる操作（検索、登録など）
resources読み込めるデータ（ファイル、レコードなど）
prompts定型の指示のテンプレート

通信の方式

stdio（標準入出力）

  • アプリがサーバーをローカルのプロセスとして起動
  • ローカルのファイルや開発環境向け
  • ネットワークに公開しない

HTTP（リモート）

  • ネットワーク越しに複数の利用者・アプリで共有
  • 認証・認可が必須
「複数のアプリで再利用したい」「独立して保守したい」→ MCP サーバー。「ローカルのファイルを扱う」→ stdio。

拡張方法の使い分け（Agentic Customization）

方法何か選ぶ場面
組み込みツールClaude Code や Agent SDK に最初からある（ファイル操作、コマンド実行、検索など）用意されているものはまずこれを使う
カスタムツール自分のアプリの中で関数を tools として定義1つのアプリだけで使う簡単な連携
MCP外部のサーバーとしてツールやデータを提供複数のアプリで共有、独立した保守、外部システムとの連携
Skills指示・資料・スクリプトをまとめた「やり方の知識」。関係するときだけ読み込まれる手順書、書式のルール、専門的な作業のやり方を再利用

MCP は「何ができるか（道具）」を増やし、Skills は「どうやるか（知識・手順）」を与える、と考えると区別しやすくなります。

この分野のまとめ

  • ツールの説明は具体的に。型を正しく。失敗も is_error で返す。
  • クライアントツールはアプリが実行、サーバーツールは Anthropic が実行。
  • MCP：tools・resources・prompts。ローカルは stdio、共有は HTTP＋認証。
  • 組み込み → カスタム → MCP → Skills を目的で使い分ける。
