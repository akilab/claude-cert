統合（Integration） 配点 19%

CCAR-P で最も配点が大きい分野です。権限の設計、精度と速度の判断、大規模な監視、RAG、連携方式の選択、コンテキストの読み込み方まで、「既存のシステムにどう安全につなぐか」を問います。

能力の肥大（capability bloat）を防ぐ

エージェントに「念のため」と多くのツールや権限を渡すと、誤動作や悪用の被害が大きくなり、ツールの選び間違いも増えます。

  1. 役割の業務を洗い出し、必要なツールと権限（読み取りのみ／書き込み）を決める。
  2. 不要なツールは設定から外す（予防：攻撃面の削減）。
  3. 残る危険な操作には、承認・フック・上限を付ける（予防：止める）。
  4. ログと監査で見守る（検知）。
ログや確認ダイアログは「検知・補完」の対策。不要な権限があるなら、まず取り除くのが最小権限の答え。

認証・認可の設計

LLM のシステムでよくある穴は、認可をモデルの判断に任せてしまうことです。

✕ 危険な設計

  • 全データを読める共通アカウントで検索
  • 「権限のない情報は答えないで」とプロンプトで指示

◯ 安全な設計

  • 質問した本人の権限で検索・絞り込み（ID の受け渡し）
  • 権限のない情報はコンテキストに入れない
  • ツールの呼び出しも本人の権限で実行

確認すべき観点：誰として（どの ID で）外部システムにアクセスするか、トークンの範囲と期限、エージェントが代理で操作するときの承認、監査ログ。

精度と速度のトレードオフ

上げると精度速度費用
上位のモデル↑↓↑
思考の量（effort）↑（難しい問題で）↓↑
検索で渡す資料の量↑ のち ↓（ノイズ）↓↑
多段の検証・評価者↑↓↑

判断の手順：① 必須の要件（例：2秒以内に出し始める）を満たす構成だけに絞る → ② その中で精度が最も高い構成を評価で選ぶ。必須の要件は「満たせば十分」な最低条件で、「速いほどよい」目標ではありません。余った時間は精度に使います。判断の根拠（評価の数字）を説明できるようにします。

候補の例：中位のモデル／上位モデルで思考を減らす（effort を下げる）／ストリーミングで最初の文字を早く出す。最も速いモデルに飛びつくと、条件は満たしても精度を必要以上に捨てることになります。

大規模な可観測性

  • トレース：1件のリクエストの中の、各モデル呼び出し・ツール呼び出しの入出力、時間、トークン、エラー。
  • メトリクス：遅延の分布（p50・p95。用語の解説）、エラー率、トークンと費用、stop_reason の割合、ツールの失敗率。
  • 品質の監視：出力のサンプリングと自動・人の評価（エラーにならない品質の低下を見つける）。
  • アラート：閾値を超えたら通知。request-id で個別の調査へ。

個人情報はトレースでも伏せ字にし、保存期間を決めます。

RAG パイプラインの設計

チャンク分割

方法特徴
固定長簡単だが、意味の途中で切れやすい
構造に沿う（見出し・段落・手順）意味のまとまりを保てる。マニュアルや規程に向く
重なり（overlap）を持たせる境界で情報が切れる問題を和らげる
文脈を付加する（章タイトル・文書名・要約）チャンク単体でも意味が分かり、検索の精度が上がる

インデックスの運用

文書の更新時の再インデックス、古いチャンクの削除、埋め込みモデルの一致（取り込みと検索で同じモデル）、メタデータ（日付・権限・版）の付与を設計に含めます。

データと問い合わせに合った検索

データ・問い合わせ向いている方法
型番・ID・固有名詞（完全一致が重要）キーワード検索（BM25 など）
言い換え・曖昧な質問埋め込みによる意味検索
両方が混ざるハイブリッド検索＋再ランキング
表・数値（集計が必要）SQL などの構造化された問い合わせ（ツールとして提供）
関係のたどり（誰が誰の上司か等）グラフや関係データベース
権限で見える範囲が違うメタデータでの絞り込みを検索時に必ず適用

連携方式の選択

方式向いている場面
API を直接呼ぶ（カスタムツール）1つのアプリの中の単純な連携
CLI開発者の環境で、既存のコマンドを使う（Claude Code など）
MCP複数のアプリで共有、提供側が独立して保守、標準化された接続
エージェント間連携（agent-to-agent）別のチーム・組織のエージェントに仕事を任せる

段階的な読み込みか、一括か

一括（monolithic context）

  • 最初にすべてのツール・資料を渡す
  • 単純。少数なら有効
  • 多いと圧迫・取り違え・費用増

段階的（progressive discovery）

  • 最初は概要だけ、必要なものを後から読み込む
  • ツール検索、Skills、サブエージェント
  • 多数のツールや大量の知識に向く

この分野のまとめ

  • 不要な能力は外す。認可は仕組みで、権限のない情報は渡さない。
  • 必須要件を固定して、その範囲で精度を最適化。
  • トレース・メトリクス・品質の監視。
  • RAG：構造に沿ったチャンク、再インデックスの運用、データに合った検索。
  • 連携：単純なら API、共有なら MCP。ツールが多いなら段階的に読み込む。
