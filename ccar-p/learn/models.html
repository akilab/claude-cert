モデル・プロンプト・コンテキスト 配点 13%

モデルの選び方、system プロンプトとテンプレートの設計、プロンプトの技法、コンテキストの最適化、プロンプトの再利用を、アーキテクトの視点で扱います。

モデルの選択

Haiku

  • 速く安い
  • 大量の分類・抽出、一次振り分け

Sonnet

  • バランス
  • 多くの本番用途

Opus

  • 最高性能
  • 難しい推論、計画役、複雑なエージェント
  • 1つのシステムでも、処理ごとに要件（品質・速度・費用）を評価してモデルを選ぶ。
  • 要件を満たす最小のモデルを選び、難しいものだけ上位に回す（ルーティング）。
  • モデルの更新では挙動が変わりうるので、評価してから切り替える。

API の詳細は Messages API 解説のモデルの章 を参照してください。

system プロンプト・テンプレート・ガードレール

  • 共通部分と個別部分を分けたテンプレートにする（モジュール化）。共通の変更は1か所で全体に反映。
  • テンプレートはバージョン管理し、変更時には評価を実行する。
  • ガードレール（禁止事項・エスカレーションの条件）は system に明記しつつ、強制が必要なものは仕組み（権限・フック）で担保する。

プロンプトの技法

技法内容使いどころ
zero-shot指示だけ単純で明確な作業
few-shot入出力の例を示す書式や判断基準を安定させたい
chain-of-thought段階的に考えさせる（新しいモデルでは思考の機能）複数の条件を組み合わせる推論
根拠の引用資料の該当箇所を示してから答えさせる規程・約款・契約書の質問
分解（プロンプトチェーン）段階に分けて処理複雑な多段の作業

コンテキストの最適化

手段内容
要約による圧縮（compaction）古い履歴を要点にまとめる
外部メモリ長期で必要な情報を保存し、必要なときに読み込む
不要な出力の削除使い終わった大きなツール出力を削る
検索で必要な分だけ資料を全部入れず、関係する部分だけ
分離サブエージェントやワークフローの段階ごとにコンテキストを分ける

プロンプトの再利用

方法何を再利用するか効果
プロンプトキャッシュ毎回同じ長い前置き（system・規程・ツール定義）費用と最初のトークンまでの時間の削減
モジュール化したプロンプト共通部分のテンプレート保守性・一貫性
Skills手順・書式・専門的なやり方の知識必要なときだけ読み込み、複数の場面で再利用
「同じ 8,000 トークンの前置きを毎回送っていて、速度と費用の両方が課題」→ 変わらない部分を先頭に置いてキャッシュ。切り詰め・モデルの縮小・few-shot への移動は的外れ。

この分野のまとめ

  • モデルは処理ごとに評価して選ぶ。
  • system はテンプレート化・モジュール化・バージョン管理。
  • 技法：zero/few-shot、chain-of-thought、根拠の引用、分解。
  • コンテキストは要約・外部メモリ・削除・検索・分離で最適化。
  • 再利用：キャッシュ・モジュール化・Skills。
