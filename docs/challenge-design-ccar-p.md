## 1. CCDV-F 版との違い

CCAR-P は「作れるか」ではなく「設計し、判断し、説明できるか」を問う試験です。対象は、通常の問題と Web 問題集をすべて解き終えた人です。そのため、知識を思い出すだけでは解けず、**問題文の条件に当てはめて判断する**問題にします。

| 観点 | 方針 |
|---|---|
| 正しさの条件 | 一般論としては正しくても、**問題文の条件のもとでは誤り**になる記述を入れる（例：「キャッシュで速くなる」は正しいが、毎回変わる部分が先頭にある構成では効かない）。どちらに当たるかは、問題文の数字・制約から必ず決まるようにする |
| 数字の読み取り | 評価結果・費用・件数の表を問題文に入れ、数字を**判断の材料**として読ませる。計算は「件数に直す」「要件と比べる」程度にとどめ、選択肢の大半が計算の答え合わせになる問題は作らない（2026-11-23 ユーザーの指摘で方針を変更） |
| 対策の種類 | 予防（渡さない・できなくする・止める）／検知／補完の区別を、選択肢の正誤の決め手にする |
| 原因の切り分け | 「何が変わったか・何が変わっていないか」から原因の層を絞る問題を入れる |
| 解けない問題にはしない | 正誤が解釈で割れる記述は使わない。判断の根拠は、問題文か学習ページ・docs に必ずある |

## 2. 追加する項目：狙い（aim）

解説の一番最初に、**この問題で何を確認しようとしたか**と、**学んでほしいこと**を示す。

```json
"aim": {
  "check": "この問題で確認すること（1〜2文）",
  "lesson": "学んでほしいこと（試験や実務で使える判断の軸。1〜2文）"
}
```

- 画面：解答すると、選択肢の上に「結果（完全正解／不正解）→ 狙い」を出し、そこまでスクロールする。続けて各選択肢の解説、最後にポイント。
- 結果画面の振り返りでも、問題文の直後に狙いを表示する。
- `aim` がない問題（CCDV-F の最難関など）は従来どおり。
- 問題文の中の `| a | b |` の行は表として表示する（`richText`。2行目の `|---|` は見出しの区切り）。評価結果や費用の表に使う。
- `tools/validate.py`：`aim` がある場合は `check` と `lesson` の両方を必須にする。CCAR-P の最難関では `aim` を必須にする。
