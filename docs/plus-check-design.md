# CCDV-F プラスONEチェック 設計メモ

作成日：2026-11-27
目的：教え子が 2026-12-04 に CCDV-F を受ける。問題演習はかなり進んでいるので、仕上げとして**用語と考え方**を短い問題で確認する。
きっかけ：ユーザーが CCAR-P を受けて、「専門用語が多くて面食らう」と感じた（インストルメンテーション、オブザーバビリティ、デプロイメント、敵対的テスト、テストセットなど）。特にテスト関係の用語とサンプルを厚くする。

## 作るもの
- **用語集**：`ccdv-f/learn/terms.html`。用語ごとに「カタカナ／英語／日本語の言い換え」「意味」「紛らわしい用語との違い」。テストと評価はサンプル（テストセット、採点のコード、採点用プロンプト）つき。
- **プラスONEチェック**：`ccdv-f/plus.html`＋`assets/data/ccdv-f-plus.json`。問題演習のエンジン（`exercises.js`）を `data-set="plus"` で使う。記録は `ccdv-f-plus` として別に保存（同期の対象にもなる）。
  - 4択の単一選択が中心。紛らわしい用語を選択肢に並べ、見分けさせる。
  - 問い方：用語 → 意味／意味 → 用語／短い場面 → どの用語・考え方か。
  - すべての問題に用語集へのリンク（`learn`）を付ける。難易度はなし（`level` は 1 で固定し、画面には出さない）。

## 根拠
- 一般的なソフトウェア工学・運用の用語（観測、デプロイ、テスト）は、特定の製品の仕様に依存しない定義で書く。
- 評価の考え方は Anthropic の公式ドキュメント「Define success criteria and build evaluations」
  （https://platform.claude.com/docs/en/test-and-evaluate/develop-tests 、2026-11-27 確認）にもとづく。
  - 成功基準：具体的（Specific）・測定できる（Measurable）・達成できる（Achievable）・目的に合う（Relevant）
  - 評価の設計：実際のタスクの分布を映し、エッジケースを含める／できるだけ自動で採点する／少数の手作業より多数の自動採点を優先する
  - 採点の方法：コード（完全一致・文字列の一致。速く確実で大量にできるが細かい判断は苦手）／人（柔軟で質が高いが遅く高い）／LLM（速く柔軟で複雑な判断もできるが、使う前に信頼性を確かめる）
  - LLM で採点するコツ：具体的なルーブリック、「正しい／誤り」や 1〜5 のような決まった形で出させる、採点の前に考えさせる、生成したモデルとは別のモデルで採点する
  - 指標の例：正解率（accuracy）・適合率（precision）・再現率（recall）・F1、コサイン類似度、ROUGE-L、リッカート尺度、応答時間、稼働率
  - 用語：held-out test set（取り分けておいたテストセット）、golden answer（模範解答）
- 敵対的テスト・レッドチーミング・回帰テストは、上のページでは確認できなかった。一般的な定義で書く。
