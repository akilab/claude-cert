# CCAR-P（Claude Certified Architect – Professional）調査メモ

調査日：2026-11-20
根拠：**公式試験ガイド v1.0（2026年7月発効）**。第三者の GitHub リポジトリ（Amey-Thakur/CLAUDE-CERTIFICATIONS）にあった写しで、Partner Academy の配布版と同じものかは未照合。
12月7日の改訂（CCAR-P も対象）は、ここではまだ扱わない。

---

## 1. 試験概要

| 項目 | 内容 |
|---|---|
| 問題数 | 63問 |
| 形式 | 単一選択と複数選択。複数選択では、選ぶ数が問題文に書いてある |
| 時間 | 120分 |
| 合格点 | スケールスコア 720（100〜1,000）。正答率ではない。分野別の正答率は合否に使われない |
| 受験料 | $175（パートナーのティアで割引あり） |
| 受験方法 | 監督つき。オンラインまたは Pearson VUE のテストセンター |
| 有効期間 | 合格日から12か月。期限内なら無料・監督なしの更新テストで更新できる |
| 前提条件 | なし。CCAR-F の合格も不要 |
| 再受験 | 不合格の後 14日 → 30日 → 90日待つ。12か月で最大4回 |
| キャンセル | ガイドでは24時間前まで |

## 2. 想定している受験者

- ソリューションアーキテクト、AI/ML エンジニア、テックリード、シニアエンジニア（中堅〜上級）
- ビジネス課題を AI ソリューションに落とし込み、セキュリティ・法務・経営層との議論にも関わる人
- 業界の例：金融、医療、小売、テクノロジー、教育、行政
- 推奨経験：モジュール設計・関心の分離・スケーラビリティなどの基本、システムアーキテクチャやプラットフォームエンジニアリングの経験3年以上、本番環境で Claude などの LLM を6か月以上扱った経験、要件定義から運用までの一貫した経験
- 対象外：入門レベルの開発者、プロンプトを書くだけの役割、技術に関わらない役割

**CCDV-F との違い**：CCDV-F は「作れるか」（API、SDK、Claude Code などの具体的な操作）。CCAR-P は「設計し、判断し、説明できるか」（トレードオフ、RAG、評価、ガバナンス、関係者との合意）。CCAR-P のブループリントにはスキル単位の配点がない。

## 3. 出題範囲（7分野）

問題数の目安は「割合 × 63問」（公式の数字ではない）。

| # | 分野 | 配点 | 目安 |
|---|---|---|---|
| 3 | Integration（統合） | **19%** | 約12問 |
| 1 | Solution Design & Architecture（ソリューション設計） | 17% | 約11問 |
| 4 | Evaluation, Testing & Optimization（評価・テスト・最適化） | 16% | 約10問 |
| 5 | Governance, Safety & Risk Management（ガバナンス・安全・リスク） | 14% | 約9問 |
| 6 | Stakeholder Communication & Lifecycle Management（関係者とのコミュニケーション・ライフサイクル） | 14% | 約9問 |
| 2 | Claude Models, Prompting & Context Engineering（モデル・プロンプト・コンテキスト） | 13% | 約8問 |
| 7 | Developer Productivity & Operational Enablement（開発生産性・運用支援） | 7% | 約4問 |

### Domain 1：Solution Design & Architecture（17%）
- ビジネス課題を Claude の AI ソリューションに落とし込む
- エンドツーエンドの構成を設計する（入力 → 処理 → 出力 → フィードバックループ）
- 構成パターンを選ぶ（ワークフロー、エージェント、拡張 LLM）
- マルチエージェントシステムとオーケストレーションを設計する
- 複雑な問題を分解する
- ビジネス価値（効率、変革、生産性、コスト、性能 SLA）に合わせる

### Domain 2：Claude Models, Prompting & Context Engineering（13%）
- トレードオフにもとづいて Claude のモデルを選ぶ
- system プロンプト、テンプレート、ガードレールを設計する
- プロンプトの技法（zero-shot、few-shot、chain-of-thought）
- コンテキストウィンドウの最適化とトークン管理
- プロンプトの再利用（キャッシュ、モジュール化したプロンプト、Skills）

### Domain 3：Integration（19%）
- ツールやエージェントの設定が過剰な権限・機能を持っていないか評価する（capability bloat）
- 認証・認可の要件を分析し、セキュリティの穴を見つける
- 精度と速度のトレードオフを評価し、設定の判断を説明する
- 大規模環境での可観測性の課題を分析し、監視の方法を選ぶ
- RAG パイプラインを設計する（チャンク分割、インデックス）
- データの形と問い合わせのパターンに合った検索方法を選ぶ
- 接続方式を評価し、連携の仕組みを選ぶ（MCP、API/CLI、エージェント間連携）
- 必要に応じて段階的に情報を読み込む方式（progressive discovery）と、最初にすべて渡す方式（monolithic context）を比べる

### Domain 4：Evaluation, Testing & Optimization（16%）
- 評価指標を決める（精度、速度、コスト、安全性、セキュリティ）
- 評価データセットとテストの仕組みを、複数の手法を組み合わせて設計する
- A/B テストと継続的な改善
- システムの問題を診断する（プロンプトの失敗、ハルシネーション、モデルの不一致）
- トークン使用量、速度、コストと性能のバランスを最適化する
- ログと可観測性ツールで性能を監視する

### Domain 5：Governance, Safety & Risk Management（14%）
- ガードレールと安全のための制御を実装する
- LLM システムのリスク、限界、失敗のパターンを見つける
- 人が確認する仕組み（human-in-the-loop）を取り入れる
- 規制に準拠する（GDPR、HIPAA、FedRAMP など）
- 倫理面の配慮（バイアス、公平性、透明性）

### Domain 6：Stakeholder Communication & Lifecycle Management（14%）
- 体系的なヒアリングと要件の収集
- 設計の判断とトレードオフを説明する
- 関係者からのフィードバックと期待値の調整（SLA を含む）
- 構成を文書化し、実装の手引きを用意する
- ライフサイクルの各段階を支援する（ヒアリング、設計、引き継ぎ、監視、改善）

### Domain 7：Developer Productivity & Operational Enablement（7%）
- チーム向けに Claude のツールと環境を設定する（Claude Code など）
- AI を使った開発の流れを改善する
- デバッグと運用上の問題解決を支援する

## 4. 公式サンプル問題から分かる出題スタイル

| # | 分野 | テーマ | 正解の考え方 |
|---|---|---|---|
| 1 | Domain 3 | サポート用エージェントが、不要な返金・アカウント削除のツールまで持っている | 最小権限：不要なツールを**設定から外す**。ログや確認ダイアログは「後から見つける・補う」対策で、権限の削減ではない |
| 2 | Domain 2 | 毎回同じ 8,000 トークンの system プロンプトと規程文書を送っている。速度とコストが課題 | 変わらない部分を先頭に置き、プロンプトキャッシュを有効にする。速度（最初のトークンまでの時間）とコストの両方が下がる |
| 3 | Domain 4 | 文書を更新した後から、RAG が自信満々に誤答するようになった。速度とモデルは変わっていない | まず検索・インデックスの段階を疑う（再インデックスの失敗、埋め込みの不一致など） |

誤答の選択肢の傾向：
- 問題を見つけるだけの対策（ログ）や、補うだけの対策（確認ダイアログ）で、原因そのものを取り除いていない
- 必要な情報を捨てる（文書を切り詰める）
- 根拠なくモデルを替える（大きく・小さく）
- 状況と結びつかない原因（モデルの重みが変わった、temperature）

→ 問題集では、**「何が変わったか・何が変わっていないか」から原因を絞る問題** や、**予防・検知・補完の対策を見分ける問題** を多めに作る。

## 4.5 受験した人の感想（2026-11-27 受験・合格、892点）

ユーザー本人が受験して感じたこと。試験問題そのものは書かない。

- **出題形式はガイドやサンプル問題から想像したものと大きく違った**
  - **ほとんどの問題が「2つ選べ」の複数選択**だった。4つから1つを選ぶ問題は意外と少なかった
  - **1つの状況文に5問ほどの小問がつき、それぞれ3択**という問題が数問あった
- 全体としてとても難しく感じた。それでも手応えより点数は高かった
- 前の週に CCDV-F を受けており、その知識が役立った

→ 問題集の形式の割合を見直す：複数選択（2つ選べ）を主にし、状況文＋3択の小問のセットも用意する。

## 5. 準備の進め方（ガイド第7章の要約）

- ブループリントの各項目を自分で評価する
- 公式ドキュメント（Claude API、モデル、プロンプトエンジニアリング、MCP、Skills）を読む
- RAG、評価、可観測性を含むエンドツーエンドの Claude ソリューションを1つ作って動かす
- モデル選択、連携方式、セキュリティのトレードオフを判断する練習をする
